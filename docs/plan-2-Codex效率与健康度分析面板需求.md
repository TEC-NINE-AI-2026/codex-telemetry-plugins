# Codex 效率与健康度分析面板需求

## 1. 背景与目标

现有 Codex 性能面板已经能够展示轮次耗时、阶段分布、Token、上下文和订阅限额。本次将其扩展为本地只读的“Codex 效率与健康度分析面板”，帮助个人用户比较模型与推理配置、识别工具和任务故障、观察上下文压力、多智能体活动、并发和工作模式。

本版本为 `1.2.0`，不接入 GitHub、OpenAI 账单、团队后台或其他远程分析服务。

## 3. 页面与筛选

页面采用“概览 + 标签页”结构，包含：

1. 概览：完成率、P50/P95、TTFT、Token、缓存、上下文风险、并发、额度和工作模式。
2. 效率：模型 × 推理强度矩阵及缓存读取/写入趋势。
3. 工具与智能体：工具调用、累计耗时、P95、失败率和匿名化智能体活动。
4. 上下文健康：峰值分布、70% 预警、85% 危险和压缩统计。
5. 任务：任务与轮次详情、工作模式、工具摘要、阶段瀑布和 Token 快照。

全局筛选包含时间范围、项目、模型、推理强度、状态和工作模式，并应用于全部标签页。

## 4. 指标口径

- 完成率 = 已完成 ÷（已完成 + 已中止 + 不完整），运行中不参与分母。
- 缓存命中率 = 缓存输入 Token ÷ 输入 Token。
- 缓存写入率 = 缓存写入 Token ÷ 输入 Token。
- 推理占比 = 推理输出 Token ÷ 输出 Token。
- 工具失败率仅统计明确归一化为成功或失败的工具状态；未知、中止和取消不进入分母。
- 上下文峰值达到 70% 为预警，达到 85% 为危险；这是面板启发式指标，不代表 Codex 官方限额策略。
- P50/P95 仅使用具备完整时间数据的已完成轮次。
- 峰值并发通过轮次开始和结束区间重叠计算。
- 多智能体不估算反事实“节省时间”，仅报告实际累计耗时、墙钟跨度和重叠率。

## 5. 数据来源与兼容

- 数据来自当前用户 `~/.codex` 或 `CODEX_HOME` 下的会话 JSONL 和会话索引。
- SQLite schema v2 为轮次增加安全维度 JSON，并扩展阶段安全元数据。
- 从 schema v1 升级时保留用户的历史清理截止时间，重建派生数据库以回填已有日志。
- 本地 JSONL 是版本化内部数据。缺失字段显示“Codex 未提供”，未知字段只进入兼容性诊断计数。
- 工作模式和自动化只接受明确字段，不根据标题、目录或消息正文猜测。

## 6. 隐私与安全边界

允许保存：任务/会话标识、标题、工作目录、模型、推理强度、安全运行维度、时间、Token、缓存、上下文、限额、安全工具类别/名称、标准化状态和哈希后的智能体关系。

禁止保存：认证文件、原始推理、工具命令、工具参数、工具输出、错误正文、原始智能体 ID、未知事件 payload 内容。服务只监听 `127.0.0.1`，API 使用每进程随机令牌，不上传分析数据。

## 7. 验收标准

- 五个标签页和六类筛选在有数据、空数据和字段缺失时均可正常展示。
- `/api/analytics` 返回 coverage、overview、efficiency、cache、tools、agents、context、reliability、concurrency 和 workModes。
- schema v1 数据库升级后自动回填，且保留历史清理截止时间。
- 多智能体标识在 SQLite 和 API 中均为稳定哈希，敏感测试字符串不泄漏。
- Windows、macOS、Linux 执行 `npm run check` 全部通过。
- 深色、浅色、桌面和窄屏布局无横向页面溢出，表格自身允许横向滚动。

## 8. 后续路线图

- Git/GitHub：代码增删行、测试结果、提交、PR、审查发现和采纳结果。
- 管理后台：团队采用率、用户/智能体排行、插件和技能使用趋势。
- 账单：准确 Credits、费用和完整计费活动；不得由本地订阅 Token 估算。
- 质量：显式用户评分、自动化验收、测试通过率和返工次数。
